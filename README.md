# Лабораторная работа № 2. Java Reflection — генератор объектов

## Реализованное решение

Требуется JDK 21

```bash
./gradlew test    
./gradlew run     
```

API генератора:

```java
Generator generator = new Generator();
Integer number = generator.generateValueOfType(int.class);
Shape shape = generator.generateValueOfType(Shape.class);
Cart cart = generator.generateValueOfType(Cart.class);
```

`Generator` использует один `java.util.Random`. Примитивы и обёртки создаются
непосредственно, константы enum выбираются случайно, массивы создаются через
`Array.newInstance`. Для пользовательских классов генератор читает конструкторы
и типы их параметров через Reflection, рекурсивно создаёт аргументы и вызывает
`Constructor.newInstance`. Конструкторы перебираются в случайном порядке до
первого успешного вызова. Поддерживаются закрытые конструкторы, если JVM разрешает
доступ через `trySetAccessible`. Поля напрямую не изменяются: состояние объекта
определяет его конструктор, поэтому конструктор без аргументов сохраняет свои
начальные значения полей. Специальных проверок имён классов из шаблона нет.

### Семантика `@Generatable`

Аннотация доступна во время выполнения (`RUNTIME`) и ставится на тип (`TYPE`).
Каждый пользовательский класс должен **сам объявить** `@Generatable`; аннотация
не наследуется. Неаннотированный пользовательский тип отклоняется. Встроенные
типы, enum, массивы и поддерживаемые коллекции не требуют аннотации.

Для интерфейса или абстрактного класса обязательна аннотация с непустым списком
`implementations`. Каждая реализация должна быть конкретным совместимым классом
и сама объявлять `@Generatable`. Весь список проверяется перед генерацией;
ошибочная запись отклоняет запрос. Корректные реализации пробуются в случайном
порядке. У конкретного класса список `implementations` должен быть пустым.
Сканирование classpath и автоматический поиск реализаций не выполняются.

Например, `Shape` объявляет
`@Generatable(implementations = {Rectangle.class, Triangle.class})`.
Для нового класса достаточно поставить аннотацию и предоставить конструктор
с поддерживаемыми параметрами. Для нового абстрактного типа необходимо также
перечислить его реализации. Тесты демонстрируют это на собственных классах,
закрытом конструкторе, record и абстрактном классе `Animal`.

### Диапазоны и ограничения

- `boolean` принимает оба значения; `byte`, `short`, `long` используют полный
  диапазон типа; `int` — от −1000 до 1000 включительно; `float` и `double` —
  от 0 включительно до 100 исключительно. `char` — латинская буква `a`–`z`,
  строки содержат от 1 до 12 таких букв. Для `Object.class` создаётся строка.
- Массивы и списки содержат 1–3 элемента. Поддерживаются также многомерные массивы.
  Для отображения генерируются 1–3 пары; совпадающие ключи перезаписываются,
  поэтому итоговый размер может быть меньше, но отображение остаётся непустым.
- Поддерживаются `List`/`ArrayList` и `Map`/`LinkedHashMap`. При запросе по одному
  `Class` generic-параметры недоступны: список содержит строки, отображение —
  пары `String`–`Integer`. В параметрах конструкторов читается `ParameterizedType`,
  поэтому работают `List<Product>`, `Map<String, Integer>` и их вложенные
  сочетания, например `Map<String, List<Product>>`.
- Другие коллекции, generic-классы пользователя с параметрами, переменные типов,
  wildcard (`List<?>`) и generic-массивы не поддерживаются. Enum без констант,
  `void`/`Void`, а также `null` вместо запрашиваемого класса отклоняются.
  Нестатические внутренние классы не поддерживаются как отдельная категория:
  их неявный аргумент внешнего экземпляра должен удовлетворять обычным правилам.
- На одной ветви графа допускается два экземпляра одного конкретного
  пользовательского типа. Следующее вхождение этого типа становится `null`,
  что завершает рекурсивные структуры, включая взаимную рекурсию. Например,
  `BinaryTreeNode` получает корень и двух детей, у детей ссылки равны `null`.
  Это предусмотренное окончание графа, а не признак ошибки; корневой запрос
  никогда не возвращает `null`. Конструкторы рекурсивных классов должны допускать
  такие конечные ссылки. Дополнительный предел глубины всех вложенных вызовов — 16;
  превышение приводит к исключению.
- Генератор не проверяет предметные ограничения: стороны треугольника могут
  не образовывать треугольник, и его площадь может быть `NaN`.

При неудаче выбрасывается `GenerationException`. Сообщение называет проблемный
тип; ошибки попыток вызова конструкторов и выбора реализаций сохраняются как
suppressed exceptions, исходные исключения конструкторов — как причины (`cause`).
Если один конструктор или реализация не подходит, генератор пробует остальные.
Повторной генерации аргументов того же конструктора в рамках одной попытки нет.

## Цель

Познакомиться с Java Reflection API и научиться использовать информацию о типах во время выполнения программы. Спроектировать генератор случайных значений и объектов, работающий не только с заранее известными классами.

## Задание

Реализуйте генератор, которому можно передать `Class<?>` требуемого типа и получить значение этого типа. Примеры запросов:

```java
Integer number = generateValueOfType(Integer.class);
String text = generateValueOfType(String.class);
Rectangle rectangle = generateValueOfType(Rectangle.class);
Shape shape = generateValueOfType(Shape.class);
int[] numbers = generateValueOfType(int[].class);
List<?> items = generateValueOfType(List.class);
Map<?, ?> entries = generateValueOfType(Map.class);
```

Это примеры использования, а не обязательная сигнатура метода. Вы можете выбрать собственный API, но должна сохраняться возможность запросить значение по `Class<?>`.

Используйте `java.lang.reflect` для исследования пользовательских типов и создания их экземпляров. Для генерации случайных значений примитивных типов и строк используйте `java.util.Random`.

Классы в пакете `classes` задают ориентир по сложности объектов. **Нельзя подменять универсальную генерацию набором специальных веток, рассчитанных исключительно на имена классов из шаблона.** Генератор должен работать и с новыми классами сопоставимой сложности.

## Обязательные возможности

### Поддерживаемые типы

| Категория | Примеры |
| --- | --- |
| Примитивные типы и их обёртки | `int`, `double`, `boolean`, `char`, `Integer`, `Double` и др.  |
| Строки | `String` |
| Перечисления | `enum Color { RED, GREEN, BLUE }` |
| Массивы | `int[]`, `String[]`, `Color[]`, `Rectangle[]` |
| Списки | `List` (хотя бы один поддерживаемый вариант списка) |
| Отображения | `Map` (хотя бы один поддерживаемый вариант отображения) |
| Пользовательские классы | `Rectangle`, `Triangle` и новые классы аналогичной сложности |
| Интерфейсы и абстрактные классы | `Shape` и другие типы с подходящими реализациями |

Для массивов обязательна поддержка как минимум одномерных массивов с элементами поддерживаемых типов. Для `List` и `Map` достаточно продемонстрировать генерацию **хотя бы одного непустого варианта** каждого вида, содержащего сгенерированные элементы и пары ключ–значение соответственно. Поддержка всех разновидностей коллекций и произвольных сочетаний generic-типов **не требуется**. Выбранные ограничения опишите в своём решении.

Размеры массивов и коллекций, диапазоны и распределения случайных значений, длины строк и прочие параметры генерации определяются студентом. Генерация не должна сводиться к постоянному возвращению одной заглушки. Генерация `void`/`Void` не требуется.

### Пользовательские объекты

Генератор должен создавать объекты пользовательских классов с применением Reflection API. Способ создания и заполнения объектов, а также выбор конструкторов остаются на усмотрение студента.

Помимо классов из шаблона, решение должно поддерживать новые подходящие классы без добавления отдельных проверок на их имена, а также классы из пакета `classes`, включая возможность запросить генерацию по `Shape.class`. В результате такого запроса должен получиться объект, совместимый с `Shape`. Аналогичное требование относится к поддерживаемым абстрактным классам.

### Аннотация `@Generatable`

Разработайте собственную аннотацию `@Generatable` и используйте её в работе генератора. Аннотация должна иметь **реальное значение для логики программы**, а не присутствовать только формально.

Правила её применения и интерпретации студент выбирает самостоятельно. В README своего решения необходимо объяснить выбранную семантику, в том числе для интерфейсов, абстрактных классов и их реализаций.

### Ошибки генерации

Если запрос невозможно обработать, генератор должен завершаться **осмысленным исключением**, по которому можно понять причину неудачи. Возврат `null` как универсальный признак ошибки не допускается.

## Дополнительное задание (необязательно)

Реализуйте генерацию значений с учётом **предметных ограничений** создаваемых объектов. Например, прямоугольник должен иметь допустимые размеры, а три стороны треугольника должны задавать существующий треугольник. Подход к решению выбирается самостоятельно; дополнительную функциональность необходимо продемонстрировать тестами.

## Тесты и CI

Напишите **автоматические JUnit-тесты**. Проверяйте как классы из шаблона, так и собственные примеры. Тесты должны подтверждать работу обязательных категорий типов, включая `List` и `Map`, создание пользовательских объектов, генерацию по `Shape.class`, выбранную семантику `@Generatable` и поведение при неудачной генерации.

Тесты должны проверять свойства полученного результата, а не требовать конкретного случайного значения.

Локальный запуск:

```bash
./gradlew test
```

В Windows можно использовать `gradlew.bat test`.

**Обязательно настройте GitHub Actions** для автоматического запуска JUnit-тестов при `push` и `pull_request`. Workflow должен находиться в `.github/workflows/`. В Pull Request должны быть доступны результаты выполнения CI. Успешная сборка без содержательных автоматических тестов не заменяет требование о тестировании.
